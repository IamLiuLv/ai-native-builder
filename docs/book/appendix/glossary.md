# 附录 B · 术语表

| 术语 | 含义 |
| --- | --- |
| **AI Native Builder** | 一个人 + AI，用 AI 原生的方式，构建从需求到交付的完整闭环 |
| **AI 原生（AI Native）** | 假设 AI 从一开始就在，站在需求的角度重新设计流程；区别于在旧流程上「贴」AI |
| **完整闭环** | 从需求到交付，并且上线后的反馈、失败能回流到下一轮 |
| **AI Native 交付质量三角模型** | 定义正确、验证正确、失败可恢复，三条边缺一不可，按顺序循环 |
| **定义正确** | 在 AI 动手之前定义「什么是对的」，本质是验收标准；软件研发中主要是 E2E 用例和 UI/UX 标准 |
| **验证正确** | 在发布之前证明 AI 真的做对了：自动化验证提供证据，人工验收做最终判断 |
| **失败可恢复** | 上线之后能快速发现、定位、修复；修不了就回滚 |
| **验收标准（AC）** | Acceptance Criteria，判断一个需求是否完成的可检验条件 |
| **Spec** | 需求规格说明，包含目标、边界、验收标准 |
| **E2E 测试** | 端到端测试，按用户的真实路径走通整个功能 |
| **Stage / 预发布环境** | 与生产环境一致、但不面向用户的环境，用于发布前的自动验证和人工验收 |
| **Production / 生产环境** | 面向真实用户的环境 |
| **回滚** | 把线上版本退回到上一个稳定版本 |
| **人工闸门** | 流程中必须由人确认才能继续的节点，比如审验收标准、Stage 验收 |
| **交付模型** | 针对某一类需求构建好的交付质量三角模型：什么算对、怎么验证、出错怎么办，以及 AI 按什么路径去执行 |
| **Skill** | 交付模型现阶段对外的表现形式：交给 Coding Agent 的一份说明书加上模板和脚本，也就是一条写下来的 AI 调度路径 |
| **样本** | 一个符合你期待的参照物，用来快速定义「什么是对的」 |
| **Coding Agent** | 能读写代码、运行命令、自主完成任务的 AI，比如 Claude Code、Codex、OpenCode |

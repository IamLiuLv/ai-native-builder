# 08 案例（下）：没有交付模型，从 0 到 1

<p class="lead">上一章，交付模型是现成的，用起来很轻松。这一章回到它诞生之前：没有样本、没有模型，一个交付质量三角模型是怎样一圈一圈转出来的。</p>

## 先说结论

canvasagents.dev 的首页，从第一行代码到今天，大约 6 周、45 个提交。把这 6 周压缩成一句话：**同一个三角模型，转了 5 圈。**

<figure>
  <img src="/triangle-rounds.svg" alt="五个由小到大的三角形，代表五轮迭代；三条边从虚线逐渐变成粗实线" />
  <figcaption>每一圈都是一次完整的「定义 → 验证 → 恢复」。上一圈失败里学到的东西，变成下一圈的定义。</figcaption>
</figure>

下面每一圈，都附上**当时真实的产出**。它们是从 git 历史里对应的提交原样构建出来的，可以直接点开看、往下滚。

## 起点：一个三条边都是虚线的三角

一开始，我对这个官网的全部想法，就是一句话：

> 给 CanvasAgents 做一个好看的官网。

| 边 | 一开始的样子 | 问题在哪 |
| --- | --- | --- |
| <span class="edge-define">定义正确</span> | 「做几版好看的官网」 | 什么叫好看？给谁看？看完要做什么？全都没说 |
| <span class="edge-verify">验证正确</span> | 我打开看一眼，凭感觉 | 感觉每天都不一样，也说不出哪里不对 |
| <span class="edge-recover">失败可恢复</span> | 交付给我，觉得行就上线；不行就让 AI 再生成一版 | 每一版都从头来，上一版的教训没有留下来 |

这就是前言里说的那种用法：一句话丢给 AI，生成、不满意、再生成。不同的是，这一次我知道自己在一个三角里，于是每转一圈，都刻意问自己：**这一圈学到了什么，能不能写进下一圈的定义？**

## 第 1 圈：模糊目标

**定义**：做几版好看的官网。我让 AI 并行做了三版。

**产出**：

- <a href="/rounds/r1-a/index.html" target="_blank">第一版：杂志风 ↗</a>：深色长文排版，每个分区配一张大图。
- <a href="/rounds/r1-b/index.html" target="_blank">第二版：明亮的产品说明书风 ↗</a>：浅色、干净，像一份技术简报。
- <a href="/rounds/r1-c/index.html" target="_blank">第三版：滚动叙事 ↗</a>：往下滚，用网页模拟产品被使用的过程，比如选中画布上的便签，投喂给终端里的 Agent。

<figure>
  <img src="/images/rounds/r1-b-0.jpg" alt="第 1 圈第二版：浅色的产品说明书风首页" />
  <figcaption>第 1 圈第二版：好看，但它在「介绍」产品，不在「演示」产品。</figcaption>
</figure>

**我的判断**：三版都「还不错」，但没有一版让我觉得「就是它」。前两版在用文字和图片**介绍**产品；只有第三版在**演示**产品，访客能看到画布、终端、Agent 是怎么配合的。

**回流**：**官网要演示产品怎么工作，而不是摆几张好看的图。** 前两版停在了这一圈，第三版滚动叙事的这条路继续往下走。

## 第 2 圈：演示要真

**定义**：滚动叙事，演示产品怎么工作。

**产出**：<a href="/rounds/r2/index.html" target="_blank">第 2 圈的官网 ↗</a>

<figure>
  <img src="/images/rounds/r2-0.jpg" alt="第 2 圈：画布上是待处理页面的截图和一句需求，旁边是实测的卡片高度、间距等数据，下方终端里 Agent 在运行" />
  <figcaption>第 2 圈：滚动叙事有了，但画面上的界面和使用方式，都是造出来的。</figcaption>
</figure>

**我的判断**：虽然它确实用了滚动叙事，但有点太假了：完全没有展示真实的产品界面，完全是造出来的产品使用方式。

**回流**：定义里加一个字，**「真」**：用最真实的产品界面，滚动演示产品的功能。

## 第 3 圈：多端炫技

**定义**：在「真」的基础上，还想表现「电脑、手机都能用」。于是做了一段设备变形动画：笔记本合上变成手机，手机再像书一样展开成折叠屏。

**产出**：<a href="/rounds/r3/index.html" target="_blank">第 3 圈的官网 ↗</a>。这就是之前在线上稳定运行过一段时间的那一版，可能有人见过。

<figure>
  <img src="/images/rounds/r3-1.jpg" alt="第 3 圈：一个复刻的工作台，左边是多个项目和画布，右边是正在运行的任务队列" />
  <figcaption>第 3 圈：复刻真实工作台，演示多项目、多画布并行。</figcaption>
</figure>

<figure>
  <img src="/images/rounds/r3-2.jpg" alt="第 3 圈：电脑、平板、手机 / 折叠屏同时显示同一份待处理队列" />
  <figcaption>第 3 圈：电脑、平板、手机 / 折叠屏，同一份队列。</figcaption>
</figure>

**我的判断**：整个效果确实蛮炫酷的，这一版也上线运行了一段时间。但上线之后，收到了一些用户的反馈：功能看起来挺炫酷，可这个功能相对来说比较通用，同类产品都有类似的功能。

**回流**：产品官网不能只放一些炫酷的动画，来演示产品的功能是什么样的，而应该聚焦在这个产品能解决什么样的问题、它的主要价值在哪里：**用滚动叙事的方式，演示产品实际能解决的问题、实际的价值，以及它在什么样的场景下发挥作用。**

这一圈最贵。整个官网的<span class="edge-define">定义</span>，被炫酷的效果带偏了；一直到后面用户反馈了问题，我才知道，这种功能和炫酷的效果，不应该放在官网的首页。

## 第 4 圈：收窄范围，只讲一个故事

**定义**：延续第 3 圈的回流，不再用炫酷的东西讲产品的功能，而是整页推倒重来，**只讲一个故事，一个真实的需求**：演示一个需求（门店在线预约），在一张画布上，从需求梳理到发布上线，一共七幕。讲清楚这个产品是怎么在真实需求的场景里，解决具体的问题、达到对应效果的。

**产出**：<a href="https://canvasagents.dev" target="_blank">canvasagents.dev ↗</a>，也就是现在线上的版本。

<figure>
  <img src="/images/rounds/r5-0.jpg" alt="第 4 圈：canvasagents.dev 第 01 幕，画布上铺开三条用户旅程的原型，右边是和 Agent 梳理需求的对话" />
  <figcaption>第 4 圈：一个需求、一张画布、七幕。</figcaption>
</figure>

**我的判断**：结合一些反馈来看，这个版本让大家能很直观地知道，这个产品能解决什么场景下的什么问题。所以我觉得，这个「讲故事」的产品演示版本是挺不错的。

**回流**：把这个经验沉淀下来，形成一个可以稳定交付的「三角模型」，本质上就是一个 Skill。

::: tip 备注
有很多同学问我 Skill 应该怎么写。其实它就是在「AI Native 交付质量三角模型」不断迭代的过程中，基于最后稳定下来的那个三角模型，自然而然产出的一个结果。
:::

## 第 5 圈：沉淀成交付模型

最后一圈不是在做官网，而是把前四圈学到的东西，打包成一个别人也能直接用的交付模型，也就是附录 A 的 product-demo-site：

| 边 | 现在的样子 |
| --- | --- |
| <span class="edge-define">定义正确</span> | 给它一个产品链接或代码库，它自己去研究产品、截取真实界面、起草方案；人只需要审一遍 |
| <span class="edge-verify">验证正确</span> | 一条命令，在电脑和手机宽度下逐幕截图并自动检查，再加一份「看图清单」和一次人工验收 |
| <span class="edge-recover">失败可恢复</span> | 可回滚地上线，上线后在几种常见浏览器里抽检；每一个线上问题，都变成下一次的验收标准 |

**产出**：<a href="/landing/index.html" target="_blank">这本小册的官网 ↗</a>，就是用这个交付模型做出来的，也就是上一章的那个例子。

## 起点和终点，并排看

| 边 | 第 1 圈 | 第 5 圈 |
| --- | --- | --- |
| <span class="edge-define">定义正确</span> | 「做几版好看的」 | 产品资料 + 一个经过四圈验证的交付模型 |
| <span class="edge-verify">验证正确</span> | 我看一眼 | 自动截图 + 看图清单 + 人工验收 |
| <span class="edge-recover">失败可恢复</span> | 不行就再生成一版 | 可回滚上线 + 抽检 + 问题回流成新标准 |

每一圈的<span class="edge-recover">失败可恢复</span>，都不只是把这一次的问题修好，而是**把失败变成下一圈的定义**：

- 第 1 圈「都不对」，变成第 2 圈的「演示产品怎么工作」；
- 第 2 圈「演示是造出来的」，变成「一切都要真」；
- 第 3 圈「炫技跑偏」，变成第 4 圈的「收窄范围，只讲一个故事」；
- 第 4 圈「讲一个故事」被验证有效，沉淀成第 5 圈的交付模型。

这就是第 6 章那句话的意思：**它是一个带方向的三角，每转一圈，交付质量就更稳一点。**

当然，第 5 圈也不是终点。产品会变，官网也会跟着变；下一次改官网，就是第 6 圈。

有现成的交付模型时，三角几乎是现成的；没有的时候，**把这个三角从虚线转成实线，本身就是最难的那部分工作**。而这还只是一个官网：一个页面，一条很短的交付链路。

下一章，我们把它放大。
